### UI Hierarchy & Layout Mechanics
1. **Rename Workspace Layout (`RenamePanel`)**:
   - Dual JList split workspace:
     - **Left Side (`RenameList` for Files):** Displays source files dropped or selected for renaming.
     - **Right Side (`RenameList` for Formatted Names/Matches):** Displays matched metadata strings generated by format evaluation.
   - Synchronized Scroll Pane (`ScrollPaneSynchronizer`): Ensures row index $i$ on the left file list is locked vertically to row index $i$ on the right match list.
   - Action Toolbar: Includes "Match" dropdown (`MatchAction`), "Format" input dialog launcher (`FormatDialog`), and "Rename" action button (`RenameAction`).
   - Context Menus: Allows row shifting (Up/Down), sorting (Alphanumeric, Natural, Date, File Size), manual row alignment, excluding rows, and clearing lists.

### Extracted Business Logic & Algorithms
1. **Match Engine Scoring:**
   - Evaluates similarity between extracted filename tokens and online provider search results using `NameSimilarityMetric` (Levenshtein distance, String similarity, N-gram sequence metrics).
   - Combines sub-metrics via `MetricCascade` and `MetricAvg` to calculate similarity scores from `0.0` to `1.0`.
   - Handles multi-episode matching (`MultiEpisode`), anime absolute numbering, and S00E00 season/episode regex extraction via `SmartSeasonEpisodeMatcher`.
2. **File Operations Execution (`StandardRenameAction`)**:
   - `MOVE`: Moves file to target path (creates destination subdirectories as required).
   - `COPY`: Copies file to target path.
   - `HARDLINK`: Creates OS hard link using `Files.createLink`.
   - `SYMLINK`: Creates OS symbolic link using `Files.createSymbolicLink`.

## Section B: Target Spring Boot Backend Specification

### Service Interfaces & DTOs

```java
package net.filebot.backend.service;

import net.filebot.backend.domain.ConflictStrategy;
import net.filebot.backend.domain.FileAction;
import net.filebot.backend.domain.LanguageCode;
import net.filebot.backend.domain.MatchingMode;
import net.filebot.backend.domain.ProviderType;
import net.filebot.backend.dto.MatchDto;
import java.util.List;

public interface RenameWorkspaceService {
    List<MatchDto> autoMatch(MatchRequestDto request);
    List<MatchDto> updateRowAlignment(List<MatchDto> currentMatches, int sourceIndex, int targetIndex);
    List<MatchDto> applyFormat(List<MatchDto> matches, String formatExpression);
    RenameExecutionResultDto executeRename(RenameExecutionRequestDto request);
}

public record MatchRequestDto(
    List<String> filePaths,
    ProviderType provider,
    MatchingMode mode,
    LanguageCode language,
    String formatExpression
) {}

public record RenameExecutionRequestDto(
    List<MatchDto> matches,
    FileAction action,
    ConflictStrategy conflictStrategy
) {}

public record RenameExecutionResultDto(
    String transactionId,
    int successCount,
    int failureCount,
    List<RenameErrorDto> errors
) {}

public record RenameErrorDto(
    String sourcePath,
    String targetPath,
    String errorMessage
) {}
```

### REST Endpoints

#### 1. Auto-Match Endpoint
- **Method:** `POST`
- **Path:** `/api/v1/rename/match`
- **Request JSON Schema:**
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "filePaths": { "type": "array", "items": { "type": "string" } },
    "provider": { "type": "string", "enum": ["THE_TVDB", "THE_MOVIE_DB", "ANI_DB", "TV_MAZE", "OMDB"] },
    "mode": { "type": "string", "enum": ["TV", "MOVIE", "MUSIC", "ANIME", "AUTO"] },
    "language": { "type": "string", "enum": ["EN", "DE", "FR", "ES", "IT", "JA", "ZH", "KO", "RU"] },
    "formatExpression": { "type": "string" }
  },
  "required": ["filePaths", "provider", "mode"]
}
```

#### 2. Execute Rename Endpoint
- **Method:** `POST`
- **Path:** `/api/v1/rename/execute`
- **Request JSON Schema:**
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "matches": { "type": "array" },
    "action": { "type": "string", "enum": ["MOVE", "COPY", "HARDLINK", "SYMLINK"] },
    "conflictStrategy": { "type": "string", "enum": ["OVERWRITE", "FAIL", "SKIP", "AUTO_RENAME"] }
  },
  "required": ["matches", "action", "conflictStrategy"]
}
```

### UI & Interaction Behavior
- **Row Alignment Mechanics:** Users can select rows on either left or right table and click "Shift Up" or "Shift Down" or drag rows to manually realign file index with episode index.
- **Visual Confidence Indicators:** Scores are color-coded in table cells: green ($\ge 0.85$), yellow ($0.60 - 0.84$), red ($< 0.60$).

## Section D: Dialogs, Modals & Edge Cases

1. **File Overwrite Conflict Dialog (`ConflictDialog`):**
   - Shows source and target paths when destination file already exists.
   - Options: "Overwrite", "Skip", "Auto-Rename (Add Counter)", "Cancel".
2. **Validate Path Constraints Dialog (`ValidateDialog`):**
   - Warns when target formatted path contains illegal OS characters (`:`, `*`, `?`, `"`, `<`, `>`, `|` on Windows).
3. **Disambiguation / Multi-Choice Series Modal:**
   - Triggered when provider search returns multiple matching series (e.g., "The Office (US)" vs "The Office (UK)").
