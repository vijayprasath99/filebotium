# Episodes Explorer & Fetcher — Parity Audit

Spec under audit: `specs/04_EPISODES_EXPLORER_AND_FETCHER.md`

## 1. Methodology

Full read of: `ui/episodelist/EpisodeListPanel.java` (314 lines), `EpisodeListPanelBuilder.java`,
`SeasonSpinnerEditor.java`, `SeasonSpinnerModel.java`, `EpisodeListExportHandler.java`;
`frontend/src/components/EpisodesExplorerPanel.tsx` (386 lines); `backend/controller/EpisodeController.java`
(full) and `backend/service/EpisodeFetcherServiceImpl.java` (full, controller AND service body, not just
interface); `WebServices.java` (grepped for provider-client wiring/API-key resolution pattern to confirm the
correct reuse target). Cross-referenced every interactive Swing element (spinner, combo boxes, popup menu,
keyboard shortcuts) against the React component tree, and every React network call against the Spring Boot
service body to detect stub/fabricated logic, per the pattern already confirmed in every other area audited
so far (Rename, Subtitles, SFV, Analyze, History, Settings, App Shell).

## 3. Ambiguous / undocumented legacy behavior

1. **AniDB client-version parameter (EP-01 side note):** `WebServices.java:60` constructs `AniDB` with version `7` (`new AnidbClientWithLocalSearch(getApiKey("anidb"), 7)`); `EpisodeFetcherServiceImpl.getProvider()` uses version `6` (`new AnidbClient("filebot", 6)`). Whether this integer is a meaningful protocol/client version that AniDB's API validates (potentially rejecting outdated versions) or a cosmetic identifier was not resolved in this pass — flagging rather than assuming either way; verify against `net.filebot.web.AnidbClient`'s constructor/usage before deciding whether `6` vs `7` matters.
2. **`net.filebot.web.SearchResult`'s actual field set** (does it carry a year at all? per EP-09) was not read as part of this audit's assigned file scope — needs one more file read to confirm whether EP-09 is a "day one" gap (backend has data available but discards it) or a "provider never returns it" limitation (nothing to plumb through).
3. **Whether `net.filebot.web.Episode`'s real `toString()`/display format matches React's hardcoded `"{series} - {S}x{EE} - {title}"` export format** (EP-11) — not confirmed; low priority since both are plausible defaults and the export already works end-to-end either way.

## 4. Reuse opportunities

1. **Fix EP-01 by deleting `EpisodeFetcherServiceImpl.getProvider()`'s manual `new XyzClient("test-key")` construction entirely and reusing `net.filebot.WebServices`'s pre-wired singletons directly**: `WebServices.TheTVDB`, `WebServices.TheMovieDB` (note: this is a `TMDbClient`, not a `TMDbTVClient` — confirm whether `TMDbTVClient` needs to independently wrap it, e.g. `new TMDbTVClient(WebServices.TheMovieDB)`, or whether `WebServices` already exposes a TV-specific variant), `WebServices.AniDB`, and `new TVMazeClient()` (TVMaze needs no key, so direct instantiation is fine, matching the legacy `EpisodeListPanel.getSearchEngines()` → `WebServices.getEpisodeListProviders()` call chain exactly, `EpisodeListPanel.java:103-105`). This single change is low-effort and fixes the most severe defect in this area — it doesn't require any new logic, only swapping the object construction source, since `net.filebot.WebServices` is already a project dependency with zero Swing coupling.
2. **Fix EP-02 by replacing every hardcoded `Locale.ENGLISH`** in `EpisodeFetcherServiceImpl.searchSeries()`/`getEpisodes()` **with a locale derived from `request.language()`** (a small mapping from the `LanguageCode` enum to `java.util.Locale`, e.g. `new Locale(request.language().name().toLowerCase())`, mirroring how legacy's `LanguageComboBox`/`Language.getLocale()` resolves the selection, `EpisodeListPanel.java:123`: `languageComboBox.getModel().getSelectedItem().getLocale()`).
3. **Fix EP-03 by having `EpisodesExplorerPanel.tsx` actually pass its `seasonFilter` state through `episodeApi.getEpisodes(...)`'s existing (already-defined, currently-unused) `season` parameter**, and by having `EpisodeFetcherServiceImpl.getEpisodes()` throw/return a distinguishable "season out of bounds" signal (a 404 with a structured error body, or a dedicated field on the response) when the filtered result is empty but the unfiltered series exists — directly modeled on `SeasonOutOfBoundsException` (`net.filebot.web.SeasonOutOfBoundsException`, referenced at `EpisodeListPanel.java:201`), which is a plain exception class with no Swing dependency and can be caught/translated to an HTTP error response as-is.
4. **Fix EP-04 (Send-to-Rename) by adding a new endpoint-free, purely client-side cross-panel data path** (e.g. lifting selected-episode state up into `AppShell.tsx` the same way `droppedFiles`/`onNavigateTab` already works for the Analyze panel's "Send to" feature — see `07_analyze_audit.md` AN-11 for the existing, working pattern to copy) rather than inventing a new mechanism; no backend reuse is needed here since the legacy version is itself pure client-side `SwingEventBus` pub/sub with no server round-trip.
5. **Fix EP-05 by exposing a lightweight `GET /api/v1/episodes/index` (or similar) backed by `net.filebot.media.MediaDetection.releaseInfo.getAnidbIndex()`/`getTheTVDBIndex()`** (`EpisodeListPanel.java:90-99` shows exactly how legacy already flattens this into a `List<String>` of effective names) if full history-tab parity is desired — this is a direct, low-risk port of existing logic, though likely lower priority than EP-01/EP-02/EP-04.
